## VERDICT: READY FOR COMMIT

## Production Bug Summary
Valid Aramina POST /demo/api/jobs requests with all required fields
(patient_id, target_side, etc.) returned HTTP 500 with ARAMINA_INVALID_REQUEST.
Root cause: FastAPI route did not extract Aramina-specific fields from
the request body and pass them to create_analysis_job. The
aramina_request was always None, triggering the "ARAMINA_INVALID_REQUEST"
guard in create_analysis_job.

## Architecture Confirmed
- Same single `POST /demo/api/jobs` endpoint for Bremen and Aramina.
- Aramina fields extracted from JSON body and validated early at route level.
- AraminaWorkflowError is caught before the generic Exception handler,
  returning safe HTTP 400 instead of 500.
- Aramina remains in-process. No HTTP provider. No external service.
- Source resolution is NOT called for invalid Aramina requests.
