# PR0132 Precommit Review — Hotfix Aramina Readiness Boundary

Branch: 0132-hotfix-aramina-readiness-boundary
PR Goal: Fix Aramina runtime readiness semantics so a manifest-backed Aramina model is considered model-ready, while missing BREMEN_ARAMINA_PROVIDER_URL is reported as a provider-boundary runtime failure instead of generic workflow_unavailable/model_not_ready.

## Production Evidence Addressed

After PR0130/PR0131 deploy, Aramina jobs returned 201 Created but events showed `reason: "workflow_unavailable", model_ready: false` and status "Workflow unavailable — model not ready". Root cause: `AraminaWorkflowProvider.readiness()` returned `model_ready=False` when `BREMEN_ARAMINA_PROVIDER_URL` was missing, causing the generic orchestrator readiness gate to block execution before `execute()` could return the intended safe provider-boundary failure.

Fix: Aramina readiness now always returns `model_ready=True` (manifest-backed). Missing provider URL is handled inside `execute()` as a safe provider-boundary failure.

## Files Changed

- `src/bremen/api/workflow_aramina.py` (+6/-3) — `readiness()` now returns `model_ready=True` regardless of `provider_url`
- `tests/test_aramina_workflow_runtime.py` (+122/-3) — Updated existing readiness test; added 4 new provider-boundary tests
