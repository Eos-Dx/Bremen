# PR0142 — Aramina preprocessing root-cause diagnostics

## Goal

Identify the exact safe preprocessing failure point for Aramina-incompatible H5 containers, especially:

- 0.2.12-beta + Nova_379 + left/right
- 0.2.13-beta + Nova_384 + left/right

Current deployed behavior after PR0141:
- public API correctly returns ARAMINA_UNSUPPORTED_INPUT
- failure_stage is preprocessing_contract
- failure_reason_code is ARAMINA_UNSUPPORTED_INPUT_PREPROCESSING_CONTRACT
- this proves failure happens before target-side/model scoring
- it does not yet identify which preprocessing transformer/stage rejects the H5

## Non-goals

Do not:
- change scoring/math
- change thresholds
- change model artifacts
- change preprocessing versions
- add Aramina external package/service dependency
- add provider URL/HTTP
- add dummy/fake/uniform fallback
- rewrite frontend
- change async/job lifecycle
- expose private data publicly

## Required behavior

1. Keep public API stable.

Top-level public failure remains:

ARAMINA_UNSUPPORTED_INPUT

Public failure_stage remains:

preprocessing_contract

Do not replace it with raw internal transformer names.

2. Add safe preprocessing subdiagnostics.

Expose only allowlisted, non-sensitive values, either in workflow failure_details.safe_details or in a nested diagnostic object:

- preprocessing_stage
- preprocessing_exception_class
- preprocessing_transformer
- preprocessing_release
- preprocessing_reason_code

Allowed preprocessing_stage values:
- worker_imports
- worker_config
- worker_pipeline_build
- worker_pipeline_execution
- worker_output
- worker_empty_output
- worker_process

Allowed exception classes:
- ValueError
- TypeError
- KeyError
- IndexError
- AttributeError
- ImportError
- ModuleNotFoundError
- RuntimeError
- OSError
- MemoryError
- redacted

Allowed transformer values must come from the existing _DIAGNOSTIC_TRANSFORMERS allowlist, otherwise redacted.

Allowed preprocessing_release:
- v0.1.7-beta
- v0.1.9-beta
- redacted

3. Add precise safe reason codes.

Map preprocessing diagnostics into stable reason codes, for example:

- ARAMINA_PREPROCESSING_WORKER_IMPORTS_FAILED
- ARAMINA_PREPROCESSING_CONFIG_FAILED
- ARAMINA_PREPROCESSING_PIPELINE_BUILD_FAILED
- ARAMINA_PREPROCESSING_PIPELINE_EXECUTION_FAILED
- ARAMINA_PREPROCESSING_EMPTY_OUTPUT
- ARAMINA_PREPROCESSING_OUTPUT_FAILED
- ARAMINA_PREPROCESSING_PROCESS_FAILED

Do not use raw exception messages.

4. Preserve private safety.

Never expose:
- S3 bucket/key
- filesystem path
- h5 path
- stdout/stderr
- traceback
- raw exception message
- env var values
- tokens/secrets
- artifact checksum/private metadata
- patient measurement arrays
- dataframe row contents
- q_range/radial_profile values

5. Add smoke script.

Create PREPROCESSING_ROOT_CAUSE_SMOKE.sh.

It should run deployed API checks for:
- 0.2.12 + Nova_379 + left
- 0.2.12 + Nova_379 + right
- 0.2.13 + Nova_384 + left
- 0.2.13 + Nova_384 + right

It must fetch fresh /demo/api/h5/containers before each POST.

It should print:
- HTTP status
- job_id
- overall_status
- failure
- failure_stage
- failure_reason_code
- preprocessing_stage
- preprocessing_exception_class
- preprocessing_transformer
- preprocessing_release
- preprocessing_reason_code
- remediation

6. Add documentation artifact.

Create PREPROCESSING_DIAGNOSTICS.md with:
- files changed
- before/after examples
- exact public/private boundary
- exact allowlists
- how to run smoke
- whether Nova_379/Nova_384 root cause was established locally
- what remains unknown without live deploy/logs
