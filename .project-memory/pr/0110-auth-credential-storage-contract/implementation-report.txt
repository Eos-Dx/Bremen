## CURRENT_CREDENTIAL_STORAGE_SUMMARY
- Credentials are loaded ONLY from environment variables via read_auth_config()
- Passwords are stored as argon2id or bcrypt hashes (validated by prefix check)
- JWT signing secret is a deployment secret loaded from BREMEN_AUTH_JWT_SECRET env var
- Auth is DISABLED by default (BREMEN_AUTH_ENABLED must be "true")
- Access tokens are short-lived (60-86400 seconds, default 900)
- Refresh tokens are longer-lived (3600-2592000 seconds, default 604800)
- Config never raises; validation errors are recorded in AuthConfig.validation_error

## PASSWORD_HASH_STORAGE_VERIFIED
Yes — Config rejects any password_hash that doesn't start with $argon2id$, $argon2i$, $2b$, or $2a$. Plaintext passwords, SHA-256, MD5, and other formats are all rejected.

## PLAINTEXT_PASSWORDS_REJECTED_OR_NOT_SUPPORTED
Yes — Config validates hash format prefix. verify_password uses argon2id PasswordHasher. No plaintext == comparison exists in verify_password or authenticate_credentials source.

## AUTH_DISABLED_BY_DEFAULT_VERIFIED
Yes — read_auth_config(env={}) returns enabled=False. Missing any required field when enabled=true also results in enabled=False with validation_error. Tests cover empty env, partial env, explicit false, and missing fields.

## TOKEN_SECRET_NOT_EXPOSED
Yes — Token responses only contain access_token, refresh_token, token_type, expires_in. Auth error shapes are generic ("Authentication failed" / "Authentication is not configured"). Validation errors never contain secret values. No filesystem paths in auth source.

## AUTH_ROUTES_PRESERVED
Yes — /demo/login, /demo/api/auth/token, /demo/api/auth/refresh routes exist in both FastAPI app and http.server handler. No source files were modified.
