CODER COMPLETE

SUMMARY

PR0122 implements two authenticated model requirements no-op endpoints and Aramina routing preparation. Both endpoints exist, are Bearer-protected, resolve known models from the catalog, return 404 for unknown models, and return honest no-op/not-available contracts. No H5 is opened, no inference is run, no jobs are created, and no reports are generated by the validate endpoint. The implementation reinforces that workflow_id is model-row routing metadata (not a global constant) and prepares for Aramina as a separate workflow family without claiming readiness.

MODEL REQUIREMENTS ENDPOINTS

GET /demo/api/models/{model_id}/requirements
  - Bearer-authenticated JSON API endpoint
  - Returns schema_version=bremen.model_requirements.v1
  - Returns workflow_id, model_version, feature_schema_version from catalog row
  - requirements_available=false, status=requirements_not_declared
  - required_fields=[], optional_fields=[], required_container_contract=null
  - Notes array explains this is reserved for future implementation
  - Returns request_id for tracing

POST /demo/api/models/{model_id}/requirements/validate
  - Bearer-authenticated JSON API endpoint
  - Accepts ModelRequirementsValidateRequest (permissive, no-op in PR0122)
  - Returns schema_version=bremen.model_requirements_validation.v1
  - Echoes container_id, source_id, upload_id, h5_path from request
  - validation_available=false, validation.status=not_available
  - inference_job_created=false, report_created=false
  - next_step.reason directs to POST /demo/api/jobs for current production path
  - Returns request_id for tracing

NO-OP CONTRACT

Both endpoints are honest no-op stubs:
  - No H5 is opened
  - No inference job is created
  - No report is generated
  - No model-specific H5 requirement fields are invented
  - Explicit status explains that raw H5 requirements belong to the future runner/preprocessing path

AUTH BOUNDARY

  - Both endpoints use _check_auth_gate (Bearer access token required)
  - No auth_ticket fallback
  - No stream/report/workspace ticket acceptance
  - No change to access/refresh token behavior
  - 401 response includes token_type="Bearer" and technical_demo_only=true

UNKNOWN MODEL BEHAVIOR

Both endpoints return HTTP 404 for unknown model_id:
  {
    "error": "Model not found",
    "model_id": "<requested model_id>",
    "request_id": "<request id>",
    "technical_demo_only": true
  }
No internals are leaked.

VALIDATION ENDPOINT SAFETY

POST validate with invalid JSON returns HTTP 400:
  {
    "error": "Invalid JSON body",
    "request_id": "<request id>",
    "technical_demo_only": true
  }
No parser internals or stack traces are exposed.

ARAMINA ROUTING PREPARATION

  - workflow_id is taken from the model catalog row, not hardcoded as "bremen"
  - model_version is audit/provenance only, not an input requirement
  - find_model_catalog_row() searches both "models" and "unavailable_models" keys
  - Aramina catalog rows can exist with workflow_id=aramina without being treated as executable
  - No Aramina catalog row was added in this PR (future scope)
  - No Aramina jobs will accidentally route to Bremen
