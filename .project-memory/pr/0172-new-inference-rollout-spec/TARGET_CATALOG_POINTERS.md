# Target catalog `runtime_release` pointers

## Schema

`bremen.contracts.inference_release.SCHEMA_ID` (`"bremen.inference-release.v1"`). `ReleaseCache.resolve()` (`src/bremen/platform/models/release_cache.py`) accepts **exactly** these four fields on a catalog entry's `runtime_release`:

```
schema_version   -- must equal "bremen.inference-release.v1"
release_id        -- non-empty string
manifest_key      -- relative S3 key; no leading "/", no ".." segments, no control chars,
                     must start with the deployed catalog's prefix
manifest_sha256   -- lowercase 64-hex SHA-256 of the exact manifest.json bytes
```

Do not add, rename, or omit fields; `resolve()` fails closed (`release_reference_invalid`) on any deviation.

## Generated fragments

`target-catalog/{a1,a2,b1,b2,b3}-runtime-release.json` — one file per model, each containing only the four fields above, `release_id`/`manifest_sha256` frozen from IR-07 evidence (`TARGET_MODEL_RELEASES.md`). Validated in this PR by `tests/test_ir07_target_catalog_pointers.py` against the real `ReleaseCache.resolve()` code path (offline, assumed empty catalog prefix).

## `manifest_key` — the one unresolved piece

Every other release file's S3 key is generated by `release_build/assemble.py::_file_ref` as:

```python
s3_key = f"releases/{release_id}/{relative_path}"
```

Extending that exact, code-proven convention, the release's own `manifest.json` belongs at:

```
releases/<release_id>/manifest.json
```

**relative to the deployed catalog's own prefix** (`BREMEN_MODEL_CATALOG_URI = s3://<bucket>/<prefix>`). The generated fragments use this relative convention verbatim, which is only correct if the deployed prefix is empty (bucket root). **This agent did not access AWS and does not know the deployed `BREMEN_MODEL_CATALOG_URI` value or its prefix.**

**UNRESOLVED — OPERATOR MUST VERIFY:** before using any of the five `target-catalog/*.json` fragments to update a real catalog entry, the operator must:

1. Read the actual deployed `BREMEN_MODEL_CATALOG_URI` (not done here).
2. If its prefix is non-empty, prepend that prefix to every `manifest_key` value (e.g. `models/releases/<release_id>/manifest.json`), consistent with `ReleaseCache.resolve()`'s check `manifest_key.startswith(self.catalog_prefix)`.
3. Confirm the manifest actually exists at that key with the matching SHA-256 **after** publication (Phase B of `OPERATOR_HANDOFF.md`) — this agent did not check for existing S3 objects.

## What must NOT change

Per `src/bremen/contracts/inference_release.py` and the existing catalog contract: updating `runtime_release` is additive/pointer-only. The following fields of each catalog entry are untouched by this spec and must not be modified as part of this cutover:

- `model_id`, `workflow_id`, artifact identity/checksum
- decision threshold / `threshold_source`
- any scientific metadata unrelated to `runtime_release`
