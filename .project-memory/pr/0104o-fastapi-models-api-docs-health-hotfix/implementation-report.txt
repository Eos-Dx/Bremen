PR0104O — FastAPI models, API docs, and health log hotfix
==========================================================

Branch: 0104o-fastapi-models-api-docs-health-hotfix
PR Target: dev
Purpose: Fix three FastAPI runtime parity issues.

SUMMARY
-------
Fixed three issues:
1. Model catalog empty — added startup event to initialize model registry
2. /demo/api-docs missing — added route using existing build_api_docs_page
3. /health access log noise — added log filter to suppress uvicorn /health logs

FIX 1: MODEL CATALOG
---------------------
Added @app.on_event("startup") handler that initializes the model registry
by calling discover_models (catalog mode) or load_at_startup (legacy mode),
mirroring the http.server startup behavior. Non-fatal on error.

FIX 2: API DOCS ROUTE
----------------------
Added GET /demo/api-docs route that reuses build_api_docs_page from
bremen.api_docs_ui. Returns HTMLResponse with X-Request-ID header.

FIX 3: HEALTH ACCESS LOG SUPPRESSION
--------------------------------------
Added _HealthAccessFilter to uvicorn.access and uvicorn loggers in
run_fastapi_server(). Filters out access log lines containing
"GET /health". Startup logs, non-health request logs, and errors
are preserved.
