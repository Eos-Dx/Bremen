## Root Cause Fixed
`get_default_registry()` imported and registered the stale `workflow_aramina_scaffold.AraminaProvider()` unconditionally, even when the real `AraminaWorkflowProvider` existed in the model registry. The real provider was only accessible via `get_provider_for_model(model_id)` (catalog-mode path). Default-registry and readiness/fallback paths used the stale scaffold.

## get_default_registry Diff Summary
Before:
```python
from .workflow_aramina_scaffold import AraminaProvider
aramina_provider = AraminaProvider()
registry.register(aramina_provider)
```

After:
```python
from .workflow_aramina import AraminaWorkflowProvider
from .model_registry import get_registry

aramina_entries = [
    entry for entry in get_registry().available_entries
    if entry.workflow_id == "aramina"
    and entry.artifact_type == "aramina.joblib.model_package"
]
if len(aramina_entries) == 1:
    registry.register(AraminaWorkflowProvider(entry=aramina_entries[0]))
```

## RegistryModelEntry Lookup Mechanism
Uses existing `get_registry().available_entries` — no new S3/catalog discovery plumbing. Filters by `workflow_id == "aramina"` and `artifact_type == "aramina.joblib.model_package"`. Only registers when exactly 1 Aramina entry exists (unambiguous).
