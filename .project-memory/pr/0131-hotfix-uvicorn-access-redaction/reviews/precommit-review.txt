# PR0131 Precommit Review — Hotfix Uvicorn Access Log Redaction

Branch: 0131-hotfix-uvicorn-access-redaction
PR Goal: Fix uvicorn access log redaction so sensitive query params are redacted without breaking uvicorn AccessFormatter.

## Production Evidence Addressed

After Aramina job startup, production logs showed `ValueError: not enough values to unpack (expected 5, got 0)` from uvicorn AccessFormatter. Root cause: `SensitiveQueryRedactionFilter` called `record.getMessage()` first, which failed for plain messages with 5-tuple args (Python's `%` formatting raised TypeError). The except clause returned early, leaving `record.args` unredacted AND `record.msg` set to a plain string with `record.args` still a 5-tuple. When uvicorn's AccessFormatter later called `formatMessage()`, it broke.

Fix applied: Handle uvicorn.access records (5-tuple args) FIRST, before calling `getMessage()`. Redact only `args[2]` (the request line) in-place, preserving the 5-tuple arity. Non-uvicorn records continue to use existing behavior.
