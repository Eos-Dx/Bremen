PR0104N — FastAPI demo UI route parity hotfix
===============================================

Branch: 0104n-fastapi-demo-ui-route-parity
PR Target: dev
Purpose: Add FastAPI route parity for legacy demo UI routes that returned 404.

PROBLEM
-------
FastAPI starts and /health returns 200, but:
- GET /demo -> 404
- GET /demo/control-room -> 404

SOLUTION
--------
Added two FastAPI routes that reuse existing legacy UI rendering code:
- GET /demo -> build_start_page() from bremen.start_page_ui
- GET /demo/control-room -> build_control_room_page() from bremen.control_room_ui

Both routes:
- Derive base_url from request Host/X-Forwarded-Proto headers
- Auto-generate X-Request-ID if not provided
- Return HTMLResponse with text/html content-type
- Reuse existing UI builders (no UI rewrite)

FIXED_ROUTES
------------
- GET /demo (and /demo/) -> 200 HTML
- GET /demo/control-room -> 200 HTML

FASTAPI_DEFAULT_PRESERVED
--------------------------
Default backend remains "http". FastAPI opt-in via:
- --backend fastapi
- BREMEN_SERVER_BACKEND=fastapi
- serve-fastapi

LEGACY_FALLBACK_PRESERVED
---------------------------
- python -m bremen serve -> legacy http.server (default)
- python -m bremen serve --backend http
- BREMEN_SERVER_BACKEND=http
