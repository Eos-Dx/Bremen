## Goal

Make Aramina failures explainable by:
model_id + patient_id + target_side.

Specifically answer:
- why 0.2.12-beta + Nova_379 + left fails
- why 0.2.13-beta + Nova_384 + right fails
- whether failures are target-side absence, preprocessing failure, profile matrix failure, LR1 failure, symmetry failure, final model failure, report failure, or unknown input-contract failure
- whether Aramina rerun/duplicate guard incorrectly ignores target_side

## Required implementation

### 1. Exact safe failure taxonomy

Keep public top-level failure:
ARAMINA_UNSUPPORTED_INPUT

Add safe structured fields for failed Aramina workflow runs:
- failure_stage
- failure_reason_code
- failure_detail
- remediation
- safe_details

Allowed failure_stage values:
- preprocessing_contract
- h5_patient_contract
- target_side_contract
- profile_matrix_contract
- lr1_contract
- symmetry_contract
- final_dataframe_contract
- final_model_contract
- report_contract
- unknown_input_contract

Do not use raw exception messages as public details.

### 2. Stage mapping

Map fixed runtime boundaries to safe stages:

- aramina_preprocessing.py / worker failure -> preprocessing_contract
- patient not present in preprocessed dataframe -> h5_patient_contract
- requested target_side has no usable rows -> target_side_contract
- empty/nonfinite/bad profile matrix -> profile_matrix_contract
- lr1_model predict_proba/input/output failure -> lr1_contract
- symmetry feature construction failure -> symmetry_contract
- final feature DataFrame missing/bad columns -> final_dataframe_contract
- final_model predict_proba/input/output failure -> final_model_contract
- report payload/report construction failure -> report_contract
- otherwise -> unknown_input_contract

### 3. Safe details

When known, include only sanitized:
- patient_display_name
- requested_patient_id
- target_side
- model_id
- model_version
- resolved_container_id basename only
- available_sides
- measurement_count
- preprocessing_release only if allowlisted: v0.1.7-beta or v0.1.9-beta

Never expose:
- S3 bucket/key/path
- filesystem path
- traceback
- raw exception text
- stdout/stderr
- env vars
- tokens/secrets
- artifact checksums/private metadata
- patient measurement arrays

### 4. Rerun/duplicate guard

Investigate and fix confirmed defect if still present:

Current suspected behavior:
_find_existing_completed_report(source_key, workflow_id, model_id)
does not include target_side.

Required behavior:
- Bremen duplicate logic unchanged.
- Aramina duplicate identity includes target_side.
- Existing Aramina left run must not block Aramina right run for same source/model.
- If full storage migration is unsafe, return precise side-aware 409 with existing_target_side/requested_target_side and document deferral.
