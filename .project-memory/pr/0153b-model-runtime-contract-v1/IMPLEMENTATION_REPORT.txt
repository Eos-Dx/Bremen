CONTRACT FORM CHOSEN
Structural typing.Protocol (runtime_checkable) in a new small module
src/bremen/model_runtime.py, following repo precedents (EventSink,
RecordResolver). Three semantic members: model_requirements(),
validate_model_input(), predict_model(). No ABC re-parenting, no base class,
no framework/HTTP/job concepts. Contract module imports nothing from
bremen.api or any model-specific science (verified by test).

BEHAVIOR IMPLEMENTED
Common platform/model boundary: platform orchestrates, runtimes own scientific
inference. Bremen 3+3 and Aramina target_side semantics coexist behind one
ModelRuntime contract. Requirements validated and predicted through the
contract; providers delegate rather than reimplement.

BREMEN RUNTIME ADAPTATION
BremenRuntime implements ModelRuntime directly; predict_model is a thin,
error-translating façade over the untouched PR0152 run(). No science changed
(preprocessing, 15-feature formulas, scaler behavior, estimator, threshold all
identical). No new wrapper layers.

ARAMINA RUNTIME ADAPTATION
AraminaRuntime adapter in the authoritative workflow_aramina module reuses the
existing pipeline; provider delegates. preprocessing/LR1/symmetry/final model/
threshold behavior, target_side semantics, source resolution, preprocessing
release selection and failure classification are unchanged externally.

WORKFLOW PROVIDER CHANGES
Both providers are now explicit platform adapters exposing model_runtime().
BremenProvider.execute() performs one predict_model() call (the PR0152
runs_runtime_once parity guarantee still passes). No provider performs
preprocessing, feature formulas, aggregation, scaler/estimator math, or
threshold application.

MODEL REQUIREMENTS INTEGRATION
Additive, behavior-preserving: runtime derives model-specific request fields
and annotates container_requirements.model_runtime. Backward-compatible:
display-only/no-manifest/no-runtime rows produce the identical PR0124 response.
No second requirements system created.

VALIDATION BOUNDARY
Model runtimes own scientific input validation (Bremen exact 3+3 shape via
validate_model_input; Aramina explicit target_side via the existing request
validator). Invalid input fails before any scientific work/scoring (parity
regression preserved). Platform validation (source existence, authorization,
routing, job identity) stays on the platform.

PREDICTION BOUNDARY
Runtimes own complete scientific inference; providers translate
RuntimePrediction.result into the established WorkflowResult payload. No new
public API fields; existing result semantics preserved.

ERROR COMPATIBILITY
Internal ownership categories only (input invalid / unsupported / configuration
required / preprocessing failed / inference failed). Public codes unchanged:
Bremen safe reason constants preserved (Incompatible: requires_exactly_3_left_
3_right, Feature construction failed: invalid_scientific_profiles,
raw_peak_gate_failed); full ARAMINA_* code/stage/diagnostic taxonomy propagates
unchanged. No paths/S3/artifact internals/tracebacks/tokens/env in errors
(runtime errors use constant safe reasons).
