# PR 0171 — IR-07: external XRD feature-library integration

Status: implementation in progress on branch `0171-ir-07-xrd-feature-library`. Not yet reviewed/approved — this document records the plan actually executed, for precommit review, not an approval artifact.

## Scope

Extract the Bremen 15-feature contract and Aramina CORE4 symmetry contracts (v0.1/v0.2) into a standalone package (`xrd-inference-features`) and bind it into each of the five current Model Releases (A1, A2, B1, B2, B3), without changing any scientific behavior, without making the library a Bremen application dependency, and without deleting any embedded legacy implementation (that is IR-08's job).

## Steps taken

1. Read the embedded implementations in full (`bremen_v01/features.py`, `aramina_v0213/symmetry.py`) and the release-build/manifest/plugin pipeline (`release_build/assemble.py`, `release_build/wheel.py`, `contracts/inference_release.py`, `ml_plugin/*`) before writing any code.
2. Created `packages/xrd-inference-features/` (hatchling, `requires-python>=3.13,<3.14`, deps pinned to `numpy==2.5.4`/`pandas==3.0.6`/`scipy==1.18.1`) with byte-identical extractions `bremen_contract.py` and `aramina_symmetry.py`, and its own isolated test suite (no `import bremen`).
3. Verified isolation by installing the package into a brand-new venv with no Bremen present and running its 15 tests there.
4. Wrote `tests/test_ir07_feature_library_parity.py`: exact-equality (`rtol=0, atol=0`) differential tests comparing the embedded implementation against the library on real frozen fixtures (`tests/bremen_3x3_helpers.make_case`) for all 15 Bremen features (including left/right-permutation invariance) and both Aramina contracts across varying target/contralateral counts and the no-contralateral neutral case.
5. Extended `bremen.inference-release.v1` (`contracts/inference_release.py`) with an **optional, additive** `feature_library` block (`ReleaseFeatureLibrary`) and a fail-closed validator (malformed distribution/version/contract, invalid SHA-256, unsafe wheel filename, missing/duplicate `feature_library_wheel` file role, filename/SHA cross-check against that file entry). Added 12 new tests; confirmed all 45 pre-existing manifest tests still pass unmodified.
6. Added `release_build/feature_wheel.py`: a second deterministic PEP 427 wheel builder (same fixed-timestamp/sorted-members technique as `wheel.py`) for `xrd_inference_features`. Confirmed byte-identical SHA-256 across two independent builds.
7. Wired `release_build/assemble.py`: `assemble_release` now also builds the feature wheel, resolves the release's real feature contract from the **actual staged artifact bytes already bound to that release** (reading the artifact's own `models[*].symmetry_feature_contract` for Aramina via the existing pickle-compat bridge; the single frozen Bremen contract otherwise) — never guessed — and emits the `feature_library` manifest block, the `feature_library_wheel` file entry, and build/summary evidence. `_feature_order_hash` now derives from `xrd_inference_features`, not the embedded modules.
8. Wired `platform/models/release_cache.py`: `_install_environments` installs the optional `feature_library_wheel` role (when present) the same way it installs the plugin wheel (`_pip_install_wheel`, no `--require-hashes`/main-lock entry needed since it is a first-party deterministic wheel, like the plugin wheel) — reused the exact same installer, no second mechanism. Added `_role_path_optional` since this role is absent on pre-IR-07 manifests.
9. Added the backend-selection seam at the two scientific runtime boundaries (`bremen_v01/runtime.py`, `aramina_v0213/inference.py`): an explicit, release-scoped `BREMEN_FEATURE_LIBRARY_BACKEND` environment variable, set only by a new `ml_plugin/release.apply_feature_library_backend` (called alongside the existing `apply_preprocessing_environment`) when the release's `runtime.json` declares one. **Not** import-presence duck typing — a differential-test process that happens to have `xrd_inference_features` importable must never silently change legacy in-process behavior. Confirmed this with a dedicated regression test and by running the full relevant suite both with and without the package installed in the dev venv.
10. Updated `tests/test_aramina_workflow_runtime.py`'s existing reviewed env-var allowlist (`test_no_external_dependency_or_execution_configuration`) to add `BREMEN_FEATURE_LIBRARY_BACKEND` alongside the existing `BREMEN_ARAMINA_DEBUG_TRACE` — this file's env-call surface is deliberately locked down by that test, and the new call is a legitimate, reviewed addition, not a bypass.
11. Rebuilt all five releases using real local build evidence already present from prior IR-03/IR-04 sessions (`/tmp/ir03/releases-final` artifacts, `/tmp/ir04/wheelhouse-all` main wheelhouse — which, unlike the then-available `/tmp/ir03/wheelhouse`, has the exactly-pinned `scikit-learn==1.9.0` wheel — and the existing `/tmp/ir03/aux-env-root` preprocessing environments). No dependency pin was changed to resolve this; the build input was located, not the policy.
12. Ran real `ReleaseCache.install()` against the rebuilt releases with a local-file-backed S3 stub and the real `pip`/`venv` installer (no mocked installer), proving: the feature wheel installs into `<digest>/env/lib/python3.13/site-packages/xrd_inference_features/`; `_smoke_golden` (full expected-result comparison, not just status) passes for every golden case in every release, including B2's exact probability/threshold/prediction gate, with the external backend active.
