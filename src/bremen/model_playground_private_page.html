ИЛЛЮСТРАЦИЯ Что является синтетическим

Пациенты, 2D-геометрия, траектория обучения, значения live metrics и Kβ proxy. Это не визуализация реальной Bremen cohort.

«Безопасно разделить» — не свойство одной формулы. Logistic regression ищет наилучшую линейную границу для training loss. Безопасность требует patient-safe validation, заранее выбранного operating point, независимой когорты, reliability rules и клинического контроля.

Kβ spectral component ≠ coefficients βᵢ

Физический смысл: Kβ — нежелательная дополнительная X-ray spectral component, способная создавать дополнительные calibration rings и искажать radial profile.

Ограничение демо: текущий ползунок не моделирует длины волн, detector geometry и дополнительные кольца. Он применяет feature-level perturbation к пяти синтетическим признакам как proxy sensitivity test.

Почему точки раньше выглядели как одна линия?

Мы одновременно сортировали пациентов по одному и тому же score и рисовали этот score по вертикали. Поэтому диагональ возникала по определению — это ranking plot, а не геометрия 15-мерных данных.

В режиме «2D-срез» показаны два синтетических признака. Там классы могут образовывать перекрывающиеся облака, XOR-подобные квадранты или кольца.

Почему текущий baseline — logistic regression?

median imputer → StandardScaler → balanced L2 LogisticRegression C=1.0 · solver=liblinear · 15 features · 188 development patients

Это прозрачный, регуляризованный и аудируемый baseline для небольшой development cohort. Он создаёт линейную границу в стандартизированном 15D feature space; sigmoid только переводит linear score в диапазон 0–1. Это logistic regression, а не обычная linear regression.

Это не доказательство оптимальности. Нелинейные модели или PCA/MCR representations должны сравниваться в patient-safe nested CV и затем на независимой когорте.

Кто создаёт коэффициенты β?

Не исследователь вручную. Люди задают cohort, labels, features, preprocessing, loss, class weights и regularization. Численные coefficients определяет optimizer на training patients.

xᵢ ∈ ℝ¹⁵ β ∈ ℝ¹⁵ zᵢ = β₀ + βᵀxᵢ pᵢ = sigmoid(zᵢ) Loss(β) = mean[class_weightᵢ · cross_entropy(yᵢ,pᵢ)] + λ‖β‖²
Featuresзадают координаты
Labelsзадают учебную цель
Optimizerищет β
Validationпроверяет переносимость

Что делает один шаг этой анимации?

errorᵢ = pᵢ − yᵢ gradientⱼ = mean[class_weightᵢ · errorᵢ · xᵢⱼ] + λβⱼ βⱼ ← βⱼ − learning_rate · gradientⱼ
Очень важно: эта пошаговая анимация использует простой batch gradient descent для объяснения. Сохранённый Bremen pipeline использует sklearn LogisticRegression с solver=liblinear. Финальная математическая задача похожа, но показанная траектория шагов не является историческим логом реального solver.

Обезличивание и validation — разные вещи. Имя и прямые идентификаторы заменяются псевдонимом для privacy. Диагноз сохраняется в контролируемой таблице, а patient/group ID используется только для patient-safe split и audit — не как признак модели. В описанной схеме 5 folds × 20 repeats этот процесс повторяется 100 раз.
Пациенты и история обучения здесь синтетические. Threshold lab предназначен только для демонстрации trade-off: изменение порога не переобучает модель и не меняет AUC. В реальной cross-validation threshold выбирается только на training patients каждого fold и затем замораживается для held-out fold.

Проверено для Aramina

Data sufficiency и reliability

High reliability: минимум 2 valid measurements на каждой груди и применимы Core4 symmetry features.
Medium reliability: на target breast минимум 2 измерения, но paired symmetry недоступна.
Low reliability: на target breast осталось меньше 2 valid measurements.
Risk ≠ reliability: низкая reliability не уменьшает p_cancer автоматически; это отдельное предупреждение.
Нужно валидировать для Bremen

Операции, рубцы и другие локальные изменения

Не писать «груди должны быть одинаковыми». Нужны стандартизованные сопоставимые измерения; естественная асимметрия существует и является частью данных.
Не утверждать направление эффекта рубца. Предыдущие операции, рубцы, импланты, радиотерапию, воспаление и выраженные локальные изменения следует фиксировать как metadata/confounders.
Не объявлять противопоказанием без данных. Нужны заранее определённые subgroup analyses и protocol rules.
Практическое правило до валидации: не смешивать чистый research cohort и postoperative cases без маркировки и отдельного анализа.
Team note · SergeyExploratory, not frozen architecture

Aramina q-binning and representation roadmap

An exploratory grid from npt 50 to 100 found npt=60 as the numerical best point, but the gain was small. It should not be presented as a proven physical optimum.

Proposed next steps: first represent profiles using PCA components, then investigate a more physically interpretable MCR representation. This is a development direction, not the current frozen Aramina model.

Формулы, которые подтверждены Aramina-кодом

Weighted RMS, region 1/2
var(q) = σT(q)² + σC(q)² w(q) = 1 / max(var(q), percentile₅(var) + 10⁻¹²) weighted_RMS = √[ Σ w(q)(μT(q) − μC(q))² / Σ w(q) ]
Wasserstein-like distance
a = clip(μT, 0, ∞); b = clip(μC, 0, ∞) a_norm = a / Σa; b_norm = b / Σb distance = Σ |cumsum(a_norm) − cumsum(b_norm)| · Δq
